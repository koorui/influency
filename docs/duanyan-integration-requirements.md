# 成果影响力评价工具：端砚接入需求

版本：2026-09-25本地实现版。依据飞书《影响力评估工具端砚系统上线》及原始输入/报告模板整理。本文是可供对接的本地文档，尚未对外提交或获得端砚资源确认。

## 当前产品流程

已有成果：关键词联想仅返回已发布结果，选择后读取同一份结果JSON展示两栏三块报告。查询保存所用版本，不冒充新模型评价。

新成果：项目方登录后按固定八部分表单填写，每份对应一个具体成果；上传材料并提交工单。管理员检查项目、原件、时间与成果范围，启动完整工作流，必要时在页面补录日期或确认冻结子成果/证据路由。模型结果先为草稿，审核发布后用户才可查询。

数据链路为：成果定位与建卡、实际Search或历史回放、原版归因、吴老师评价、v19七维与双层、独立结果导出。吴老师评分不作为v19的原始依据；两套等级不按数字合并。

## 已实现的表单和材料

| 内容 | 本地行为 |
| --- | --- |
| 项目、成果名称与形态 | 固定字段，拒绝空白和非法枚举；语义范围仍在成果定位阶段确认 |
| 成果描述、AI作用 | 说明产出、问题、新增内容；涉及AI时必须说明实际环节 |
| 单位、负责人/核心成员 | 保留提交内容及贡献说明，不从机构相同推定团队成员关系 |
| 论文/专利/软件等清单 | 允许名称、编号和链接，作为待核线索 |
| 指标与对照基线 | 可选；不强迫无依据估算 |
| 应用或外部验证 | 可选；不把项目自报直接当独立使用 |
| 支撑材料 | 文件、文件夹、ZIP逐项处理；TXT/MD/PDF/DOCX/XLSX支持文字提取 |
| 时间边界 | 项目执行起点、评审/统计截止日和依据；未知可先交工单，检索前补齐 |

前后端校验长度、格式、日期和附件归属，提交请求编号防重复。提交失败保留当前页面内容。独立保存未提交草稿及跨设备续填暂未实现，不作为已具备能力承诺。

原件保存在后端storage，MySQL保存索引、用途、SHA256、提取正文、工单与结果。已把有机化学.zip对应6份文件入库并核对全部原件哈希。项目材料、参考/既有评价、流程说明分开；后两类不能进入原始证据评测。

## 可对接接口

| 能力 | 当前接口 |
| --- | --- |
| 身份 | POST /api/auth/login、/register、/logout；GET /api/auth/me |
| 已发布成果 | GET /api/projects/suggestions；POST /api/search；GET /api/results/{id} |
| 固定成果提交 | POST /api/submissions；GET /api/submissions/{ticket_id} |
| 用户附件 | POST /api/submission-materials/batch；仅可关联本人上传材料 |
| 工单 | GET /api/tickets；管理员 /api/admin/tickets |
| 材料管理 | /api/admin/materials、/batch、/{id}/purpose、/{id}/download |
| 完整工作流 | /api/admin/pipelines 创建/详情/补充，/{id}/resume、/cancel、/artifact |
| 独立报告 | /api/admin/pipeline-reports/{id}、/{id}/draft；v19原始底稿独立下载/预览 |
| 审核发布 | /api/admin/results 及版本、编辑、发布、撤回接口 |

接口以运行服务的 /docs 和OpenAPI为准。普通用户不能查看管理底稿或未发布结果。来源变化后旧草稿不能直接发布，重新导入生成新版本，不静默覆盖已发布稿。

## 模型与工作区

当前通过Codex CLI承接模型请求，使用gpt-6-astra、medium及本机已有认证；这是后端调用，不把Key交给前端。v19保留原版计算/编排规则，平台只负责输入映射和模型传输。API调用、响应、来源与失败记录留存。

部署到服务端需由运维配置受授权的Codex执行环境和服务凭据，不能假定另一台服务器能使用本机认证状态。工作区、模型可访问目录、网络出口和运行账号需要与端砚方确认。

## 本地范围与上线前需确认的资源

本地已验证MySQL容器、Windows原生API/worker和前端；完整容器部署与端砚联调未实施。前端建议先通过应用卡链接进入独立页面；是否嵌入、SSO令牌/签名、角色映射由平台方确定，不假设已有内部接口。

需确认：

- 部署域名、HTTPS与同源代理；身份映射、管理员和材料访问权限。
- 模型服务、并发与超时、日志保留、公开资料网络访问条件。
- MySQL及原件存储位置、配额、备份和恢复；两者需一起备份。
- 业务日期采用的时区与评审截止口径；请求日志保留实际时间戳。
- 上传代理限制须与后端配置一致，后续如需分片/断点续传另行开发。

当前上限：单文件200MB、单批200个/合计2GB，批次ZIP展开5GB，PDF1000页，单次提取文本60万字。扫描件需先OCR；暂无断点续传。管理列表默认最近200条，联想最多20条；大规模分页/搜索扩展需纳入后续资源与产品要求。

## 验收与移交

本地后台63项测试在SQLite与隔离MySQL测试库均通过，通用浏览器7种场景及新表单/真实报告专项浏览器验证完成。原始约101MB ZIP经HTTP批量入口处理，6份原件下载后哈希一致。真实拉曼案例的Search、归因、吴老师和v19均有实际执行记录，两套结果保持待审核。

具体运行标识、失败恢复和科研证据缺口见 [验收记录](live-pipeline-acceptance-20260925.md)。交付包括源码、迁移、运行说明、无凭据的Skill包、接口说明、测试与证据台账。项目方与端砚方确认资源和接口后，再安排联合联调及上线。
