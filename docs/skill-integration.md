# 历史设计记录（接入前）

最新实现见 [Codex Skill接入](codex-skill-integration.md)。下文为此前仅mock阶段的设计，实际代码已支持Codex。

# 后续 Skill 接入契约

当前仅实现 `MockAdapter`，未调用 Codex、OpenAI API 或任何付费模型。模拟结果没有等级，且无法通过编辑 JSON 去除演示标识。

## 用户固定表单

`POST /api/search` 只接受 `project_id`、固定枚举 `task_type` 和至多300字 `detail`。成果须已发布；不接受自定义 prompt 或额外字段。联想由 `GET /api/projects/suggestions?q=...` 查询数据库中的已发布记录。

`backend/app/query_prompt.py` 定义 `project-query-v1` 模板，服务器将成果 ID、标题、报告版本、任务方向、补充说明作为 JSON 数据填入固定段落。补全模板和表单写入 `query_records`；用户记录按账号／访客会话隔离，管理员可检查模板。

目前返回已有报告并明确标注未执行新的核验。模板已准备且持久化，但不会自动调用 Skill；正式接入时需确定此“用户查询模板”和“管理员材料评价 Skill”是否是独立任务，不能将已有报告当作新评价输出。

## 接入位置

`backend/app/evaluator.py` 的 `EvaluationAdapter` 协议是评价边界：

输入：成果标题、检索关键词、材料列表（ID、原始文件名、提取文本）。
输出：`backend/app/schema.py` 的 `Evaluation` 对象。机器可读契约由 `GET /api/evaluation-schema` 导出。具体 Skill 输出不同字段时，由新适配器映射到此契约。

收到 Skill 后先核验其 SKILL.md、脚本依赖、联网要求、模型认证方式及材料读取方式；再确认通过 Codex CLI / SDK 等实际受支持方式执行。不能把桌面端当作 HTTP 服务，也不能认为普通模型 API 会自动执行 Skill。若仅有评价说明而无工具依赖，也可另行实现模型 API 适配器。这些是待确认路线，不是已实现接口。

新增适配器时在 `get_adapter` 注册，服务端配置 `EVALUATION_ADAPTER`；禁止从浏览器传入任意系统命令、可执行文件路径或 Skill 目录。应以低权限隔离工作目录运行，每任务固定材料副本与 Skill 版本。材料中的指令作为资料内容处理，不允许覆盖评价规则。

## 必须补充的执行保障

- 限定总时间、费用、材料大小，超时真正终止模型/CLI 子进程，保存原始输出和错误。
- 不持有数据库写入凭据；评价器只返回结果，后台负责校验和持久化。
- 证据记录文件 ID、页码/章节和原文摘录；不能仅输出没有来源的等级。
- 外层 JSON Schema 和交叉引用校验通过后生成草稿；发布仍需管理员审核。
- 记录实际模型、Skill 内容版本/摘要、输入文件摘要。当前 mock-v1 为固定内置规则，任务记录 mock-deterministic。
- 正式适配器应增加真实样本测试，评判格式、引用真实性与可重复性。不要将模拟流程测试视为评价质量验证。

## 队列设计

第一版使用 MySQL `evaluation_tasks` 作为持久队列，无需 Redis。API 入队与工单状态在同一事务提交；独立 worker 通过条件更新领取任务，重启后继续领取未开始任务。完成时检查任务状态及执行次数，防止已失效执行覆盖新结果。

超过10分钟的运行记录标记为失败，可由管理员重试；需要另一轮 worker 轮询触发回收。当前模拟适配器立即完成，未来真实调用必须实现可中断超时。高并发时可替换为 Redis + RQ，并保留当前任务及结果表。
