# 项目评测流程

管理员建立项目，设置项目日期与评价截止依据，上传原始材料并选择默认用于评测的材料。用户登录后用安全码加入项目，选择项目、填写成果名并提交需求。

工单先进入待受理。管理员在工单与工作流页面点击“受理并启动”，后台依次执行成果卡、外部Search、贡献归因、双层影响力评价。界面四步对应底层六阶段，材料缺失和范围歧义可补充后继续。

## 统一评价技能

`skills/unified-impact-evaluation` 融合 Wu 建卡与管理者报告、v19 七维及双层综合。两种能力共同读取 `references/grading-standard-20260925.json` 和配套说明，不再维护两份等级表。新结果使用 `unified-double-layer-impact.v1`，规则来源版本为 `grading-20260925-1930`。

七维G档是证据成熟度，整体L级是成果影响状态，不求和、不平均。D6不限特定机构；D7要求独立评价、采用或认可。完成评价给明确等级；成果身份不清或没有原始材料时先补输入。

## 结果与交付

管理者和七维底稿分别保留；统一结果对照L级及各G级并指出差异，不能直接取高。后台接口 `/api/admin/pipeline-reports/{id}/double-layer` 仅管理员可用。用户只能查看自己有权限的项目报告。

全部阶段成功且报告通过完整性和材料归属校验后交付用户。用户可以查看两份依据并验收。历史结果保留原版本，未按新标准重评时明确显示历史或混合版本。

导出包含 `wu-evaluation.json`、`v19-evaluation.json`、`unified-evaluation.json` 和 `manifest.json`。工作目录为 `backend/storage/pipelines/<id>/`。运行日志、凭据、材料和本机环境不随代码提交。

检索请求、正文获取和证据支持强度分别保留。历史回放不冒充新检索；失败网页不冒充已核验原文。不要直接修改运行目录状态或删除执行锁。
