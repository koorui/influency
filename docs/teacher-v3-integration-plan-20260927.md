## 四、统一数据契约

计划采用新的结果协议 `outcome-evaluation.v3` 与内部规则版本 `grading-20260927-teacher-v4`。名称用于区分现有 audit-v3 与老师附件 v3；实施时一次性登记，不能给旧报告改版本。

### 4.1 五类对象及其关系

1. **成果定位**：项目 ID、主对象 ID、名称／别名、类型、版本、形成时间、评价截止日、范围说明、关联对象、原始依据。保留现有十二字段成果卡，新增先前基础、项目新增主张等扩展字段，不在历史卡上强插字段。
2. **主张账本**：一条只表达一个可核验主张；记录提出者、数值／单位／条件、所属对象、时间和来源。区分支持、部分支持、表述需限定、冲突和缺失；项目材料有原文不等于外部独立核实。
3. **证据账本**：保留 source ID、材料 ID、原文、页码／位置、链接、事件日／公开日／取得日、独立性、能证明与不能证明什么、同源关系、可访问状态。截图只能引用真实保存的材料页，不生成“示意证据截图”。
4. **事实账本**：事实 ID、对象 ID、事实描述、F 类别、核验状态、支持及反对证据、时间资格、使用者／任务／结果、关系判断、需专家确认之处。
5. **评价快照**：引用以上冻结数据，保存六条独立判断轴、候选等级、达级事实、边界、七维审阅、任务、模型／规则／协议版本与复核记录。

新增内容沿用项目访问控制，不把私有证据改为公共链接。来源页面失败时展示已存原文与取得时间，不能把可点击 URL 当核验成功。

时间资格采用显式模式：默认沿用每轮任务既定截止日，不以原型的 2026-09-23 覆盖已有窗口。评价“当时可公开核验的影响”时，截止日后公开的来源不进入当时证据集；评价“截至当日已发生的作用”且接受事后原始记录时，可用晚取得的材料佐证此前事件，但必须标为事后佐证，明确事件时间与来源，并单列在对照中。未声明采用事后佐证模式时维持现有时间过滤；日期不明不自动判定合格。

### 4.2 事实状态与未发生的区别

保留附件四类核验状态：`verified`、`possibly_happened_but_unverified`、`not_found_as_of_cutoff`、`conflict`。另设 `assessment_status=pending/completed/not_applicable`，表达本轮尚未检查和不适用，不能把它们伪装成未发现。

`verified` 必须说明究竟核实了什么：核实“项目报告写了该指标”和核实“指标本身成立”是不同主张。已核验事实可来自可追溯的项目原始记录，是否独立另行记录，不将所有项目证据一概排除。

明确的“尚未发生”使用带证据的否定事实（例如责任方确认截止日前未开展使用），不从 `not_found_as_of_cutoff` 自动推出。搜索覆盖和来源不可取得分别记录；关键来源打不开但仍有待核线索时，不写“已核实没有”。

F1—F6 对应形成验证、真实任务使用、独立外部采用、持续多主体影响、领域稳定依赖、工作或研究方式改变。允许一个事实支撑多个层次但不重复计数，不要求每类都先为真。科学发现的实际学术采用也是作用事件，不强制转换成商业交付。

### 4.3 L 与 G 的可空规则

- 七维始终保留 D1—D7；每维必须有 `assessment_state`：`assessed / insufficient_evidence / not_applicable / conflict / not_assessed`。
- 只有 `assessed` 可以给 G1—G5，并说明对应条款和依据；其余状态 `grade=null`。G1 也需要本档事实，不能只凭材料少。
- `not_assessed` 代表尚未完成维度审阅，不能作为完整报告通过导出。`insufficient_evidence / not_applicable / conflict` 是合法的审阅结果；关键冲突须在报告和复核状态中显示。
- 对象不清、基本验证不足、关键事实冲突无法排除时允许 L 为空，报告仍能作为“待定位／待核验报告”交付；不能虚构 L1，也不能误标技术故障。
- 等级改变基于事实判断的变化。补交材料可以证明早已发生的事实，记录为“证据补充导致判断更新”；不宣称材料数量本身创造了影响。

### 4.4 四条状态线

| 状态线 | 表达内容 | 关键规则 |
| --- | --- | --- |
| 处理状态 | 排队、运行、完成、失败 | 来自真实流水线；完成不代表确认科学结论 |
| 认定状态 | system_preliminary、expert_confirmed、formal | 未记录实际专家复核时只能是系统初判 |
| 发布状态 | 草稿、已发布、被新版本替代／撤回 | 系统初判可发布供审阅，必须明确标注 |
| 用户验收 | 未验收、已验收及操作者／时间 | 仅确认收阅，与专家认定完全分离 |

专家对一个事实确认，只改变该事实的复核记录。整份报告标记 `expert_confirmed`，还需指定专家提交对当前快照的整体复核，且关键分歧已处理。`formal` 另需项目已配置的正式认定规则与获授权人员的明确操作；未配置时不开放该操作，不能由模型或普通管理员单击替代。

历史 `evaluation_status=formal` 在展示适配层解释为“系统评价已完成，未记录专家确认”，保存其原始字段。数据迁移不得将过去的发布、管理员编辑或用户验收自动转换成专家行为。

## 五、评价流水线与 Skill 改造

保留六阶段任务的调度与续跑能力，内部按下列顺序流转：

```text
定位主对象、成果卡、原子主张
          ↓
项目原文核验 + 外部证据检索 + 比较语义与归因
          ↓
冻结共用事实包（对象、截止日、证据、F状态、价值与归因依据）
          ↓
事实导向候选L判断 ──→ 七维逐项审阅与独立综合
          ↓                    ↓
              规则与引用核查、分歧归并
                         ↓
              系统初判报告 + 具体复核任务
                         ↓
              专家事实复核 → 新评价快照
```

实现细则：

1. 建卡阶段输出对象和主张；检索、归因仍使用原始资料，不读取另一条路径的等级作为证据。
2. 管理者评价阶段增加事实包准备步骤。七维阶段读取同一事实包与原文，再独立作维度解释；可发现漏证和矛盾，但新增发现先回到账本，经核验后产生新快照，不能偷偷改冻结输入。
3. 七维综合仍可给独立候选 L，用于审阅；不因“七维是证据”而删除现有有用的核查能力，也不把候选 L 输入七维分档要求其追随。
4. 组合器区分事实分歧、规则应用分歧、证据覆盖差异、非关键 G 分歧。两路一致仅表示未检测到分歧，不是专家认证。
5. 关键分歧尚未解决时不自动取高、取低或平均；`current_level` 可以为空，保留双方候选与依据，首页显示“等级待复核”。无阻断争议时展示事实导向的系统建议，并保留七维审阅详情。
6. 导出检查对象唯一、七维状态完整、引用有效、日期合格及状态一致。合法“待核验”可交付，不再通过强填等级换取阶段成功；缺字段、未知引用等技术错误仍阻断。
7. 事实包的持久化放在现有阶段产物中，不默认再增加一串模型调用。保留六阶段外部调度接口，必要的内部子步骤有独立状态和失败原因。
8. 外部实时检索与固定证据回放分开记录；同一轮运行锁定规则版本，失败续跑不能混用新旧协议。

Skill 主文件保留必要流程与禁止项，详细状态、成果类型示例及前端写作要求放到 references。等级名称、G 条件、状态定义由统一机器规则提供；提示词、结构化 schema、CLI 入口、两种传输方式和导出同步更新。新附件作为设计来源登记，不直接覆盖旧名称的兼容入口。

建议交付物兼容附件八类产物：`outcome-resolution.json`、`outcome-card.json`、`claim-ledger.json`、`evidence-ledger.json`、`evaluation-result.json`、`report.html`，以及有真实需要时的项目补证稿和专家复核任务。新增事实包作为内部可追溯产物。既有阶段原始响应和修正记录继续保存。

## 六、页面与交互方案

### 6.1 报告默认首页

沿用原型浅底、深蓝标题、克制的边框和留白，复用现有组件与样式变量。保留系统导航、项目面包屑和权限边界；左侧只列当前获授权项目内可查看的成果，切换成果使用真实路由，支持刷新和直接链接。

左侧为“成果列表＋当前成果送检材料”；正文三块：

1. **影响力判断**：成果对象与版本、截止日、认定状态、事实摘要、建议 L、可点击的达级事实、当前边界、可选的下一阶段条件与更高阶段参考。正式表述使用“现有证据为何不足以支持更高阶段”，不把未证明写成确定未发生。L6 展示维持依据与变化观察，不虚构更高级。
2. **关键判断与证据**：固定三个问题——成果价值与先进性、AI与项目贡献、实际影响。两列明确区分项目方主张和评价核验。AI与项目贡献展开后分成两个独立结论；没有材料就明确缺口。未来潜力另作带限定的说明。
3. **下一步任务**：一行摘要、类别、当前状态及“查看任务”；有关键争议置于前方，没有任务显示“当前无必须补充事项”，不为填页面制造任务。

七维矩阵、规则说明、完整归因、原始两份报告与所有差异放在“评价依据”详情。首页保留关键冲突提示及跳转入口，不能为页面简洁隐藏分歧。移除“/6”这类容易被理解为分数的附属表达，以 L 名称和标尺说明其类别含义。

### 6.2 证据查看

统一 EvidenceDrawer：来源标题、原文、材料页码／位置、真实页面截图（有则显示）、事件／公开／取得时间、核验状态、独立性说明、能证明／不能证明、关联事实。所有来源先进入同一详情，再由用户打开原文件或外链；正文不显示裸 P/E/D/G 编号。

来源标题、正文和引用不使用按数组位置拼接的关系；内部 ID 固定，前端安全呈现文字及允许的链接类型。未知引用要明确报错，避免悄悄空白。

### 6.3 任务与重新核验

- 补证草稿同一数据源支持编辑、保存、预览、复制和导出；带更新时间及编辑版本，避免刷新丢失或他人覆盖。
- 任务关联缺口／主张／事实、成果版本和评价快照。状态为 draft、open、submitted、resolved、cancelled；解决必须关联新增材料或复核记录，不能点击“完成”就改变等级。
- 补证、专家核验、试用观察、维护分别呈现。没有采用证据时可建议核实已有使用记录或观察真实试用，不能要求补一张证明即可升级。
- 收件人和截止日均不编造；默认不设置有约束力的七日期限。本轮提供发送稿，不接自动邮件、不展示假的发送成功。
- “重新核验”提交真实任务，指定新材料／截止日／范围；沿用现有项目权限和允许发起任务的角色。重复点击不能创建重复任务；任务执行时仍可看旧报告，成功后形成新版本。
- 专家选项无默认代选；支持“部分支持／证据不足／存在冲突”及说明。提交需保存所选项与文字，不用“复制文案”冒充保存复核结果。

### 6.4 必须覆盖的页面状态

对象待确认、无基本验证、七维有空档、无外部检索结果、关键分歧、历史版本缺字段、未授权、材料不可访问、排队／重试／失败、任务草稿未保存、L6、长成果名及长引文。窄窗口改为纵向卡片；125% 缩放仍可读，弹窗支持键盘操作与焦点返回。

## 七、专家复核、权限与历史

复用账号与项目成员体系，新增按项目／报告分配的审阅权限，不把所有管理员默认当作领域专家。建议增加以下独立记录，避免把多人的可变任务直接覆盖到已发布结果 JSON 中：

- `evaluation_review_assignments`：指定审阅人、项目、成果／报告范围、授权起止与分配人。
- `evaluation_review_decisions`：任务、事实／结论 ID、所审快照版本、结论、理由、证据、操作者和时间；已提交记录追加修订，不原地覆盖。
- `evaluation_followup_tasks`：任务类别、关联快照／事实、草稿正文、版本、负责人／截止日（可空）、状态和解决依据。

继续复用 `ResultVersion` 保存报告快照，并以 `supersedes` 或等价关联明确新旧结果关系。记录稳定成果 ID 与对象版本；更换主对象不作为同一成果“升级”，必须显式确认是否是关联成果另评。

API 职责按报告展开：读取审阅包与历史、保存任务草稿、提交专家事实意见、提交当前报告整体复核、发起新评价。服务端校验项目范围、角色、所审版本和当前版本；冲突返回版本已变化，不能把对旧结果的签认挂到新结果上。

动态记录区分事件发生时间、证据取得时间和评价时间。新版本可能维持、上升、下降、撤回或改为待定；每次解释原因是新增作用、补获旧事实证据、纠错、规则调整还是范围变化。已认定快照不自动被新证据覆盖，新版本重新处于系统初判。

## 九、效果对照与验收方案

本轮计划不执行测试或模型重跑。后续实施完成后，沿用已有检查，只补覆盖新增语义和跨层接口的必要验证；不为低风险文案修改新增测试。

### 9.1 四组对照，避免把不同版本混在一起

| 组别 | 输入和用途 | 如何解释 |
| --- | --- | --- |
| 历史组 | 保留已完成的旧版与 expert-v2 实跑 | 真实历史基线，不能重新标作 audit-v3 |
| 固定证据 audit-v3 组 | 对同一冻结材料／证据执行当前已修复规则 | 补齐上一轮尚未完成的真实模型效果证据 |
| 固定证据融合版组 | 同一材料、对象、截止日、模型设置，执行 teacher-v4 | 主要观察规则与协议改变的效果；若需人工映射新字段，记录映射且不得添加新事实 |
| 实时完整融合版组 | 新建卡＋真实检索＋全部评价步骤 | 观察实际产品效果；单独报告检索变化，不当作纯规则消融 |

固定输入不能手工填写期望等级。保持模型与推理设置一致，记录耗时、失败与续跑次数、证据覆盖、人工修正和调用成本（有实际数据才报告）。不预设“两边一致”或“等级提高”就是成功；若有随机分歧，先定位事实和规则原因，再决定是否需要补跑。

### 9.2 成果与边界样例

| 样例 | 必须观察的行为 |
| --- | --- |
| 拉曼探针产品 | 验证与真实成像／科研任务使用分开；内部制备流程不直接给产品 L2 |
| 拉曼设计方法 | 作为单独明确的对象；核实方法已在真实研发任务产生作用后才讨论 L2，不借用探针名下的全部影响 |
| NMRexp | 核实训练、真实评测与镜像的区别；独立关系、版本、时间和持续采用分别判断；不把规模全归 AI |
| 只有计划或验证不足 | L 可为空，给出事实缺口而不是虚构 L1 |
| 科学发现被后续研究实质采用 | 学术实际作用可被识别，不因无产品销售而压低 |
| 单次试用与长期依赖 | 分清 L3/L4/L5 对事实状态的要求，不用人数或访问量代替 |
| 论文／转载／下载／标准发布 | 不单凭形式或流量判独立采用和重大引领 |
| 私有原始使用记录 | 在有权限、来源可追溯且关系清楚时可作为证据，不要求一定有公开网页 |
| 时间越界或相互矛盾 | 不冒充截止日前已验证事实；允许争议和待核验 |
| 无 AI 因素、维度不适用、L6 | 流程和页面正常完成，不强填归因、G 或更高级 |

前两个真实成果优先实施。其余无实际材料时只作为规则边界样例或验证夹具，不能充当真实项目效果统计。专家尚未审阅时明确“专家一致性未验证”，不由系统自评替代。

### 9.3 完成标准

- 每个正向达级事实可追溯到同一对象、符合截止日要求的原始依据；未知引用、阈值提升率、无依据 AI 净增量不能通过交付。
- D1—D7 审阅覆盖完整，但缺证／不适用不再被强填 G1；关键冲突能够进入合法待复核状态。
- 没有实际专家记录时，所有入口及导出均不出现“专家已确认／正式认定”。历史 `formal` 不改变原结论和身份。
- 老报告仍可打开，原等级、版本、原文和差异保留；新字段缺失用历史状态说明，不补造 F 事实。
- 主报告无需打开七维矩阵即可读清“成果是什么、实际作用是什么、建议等级为何成立、边界在哪里”；需要时可沿事实进入来源。
- 补证草稿保存、预览、复制、导出内容一致；专家意见连同选项、理由、依据、操作者和版本可追溯。
- 重新核验产生真实且不重复的任务，新结果形成新快照；用户验收不改变认定状态。
- 项目权限和私有材料访问不退化，错误版本的专家提交不能覆盖当前报告。
- 桌面、125% 缩放和窄窗口可读，无横向页面溢出；空值、长文本、失败和争议状态均有清楚表达。
- 对照报告说明哪些变化由规则、证据、对象或日期引起，不以更高等级、单例一致或前端观感宣称准确率提升。

## 十、迁移、发布与回退

采用增加字段／表与新协议读写器的迁移，不破坏旧结果 JSON；历史先读适配，不批量重算。规则与协议版本在任务创建时锁定；已运行的旧任务由旧兼容处理器完成，若必须转新版则创建新任务并保留关联，不能接续旧任务却改口径。

先在新任务启用新协议，确认用户页、管理员页、导出和专家记录读取同一快照后切换默认。旧运行没有新增字段时显示缺少记录，不用今天的规则给它补上当年的判断。

部署从当前完整源码生成可复现交付，替换仅向现有容器复制补丁的临时方式。发布前备份数据库、材料引用、运行产物和现有程序；发布记录写明源码版本、规则、协议和数据库迁移版本。回退保留新增记录，切回兼容读取路径，不通过删除历史来恢复旧界面。

最终交付包括：统一维护的 Skill 与参考规则、新协议与兼容适配、事实驱动报告、可用的证据／任务／专家复核入口、对照分析、部署与回退说明，以及标注实际完成状态的 34 项修改清单。实际发信、GitHub 发布和正式认定制度配置不在本次“制定计划”操作中执行。
