# 事实驱动评价融合实施与效果记录

本文件记录 [完整计划](teacher-v3-integration-plan-20260927.md) 获准后的实施。规则版本为 `grading-20260927-teacher-v4`，结果协议为 `outcome-evaluation.v3`，数据库增量版本为 `0015`（新增审阅表及明确的复核顺序）。工作区原有的 14 项修订继续保留。

## 已实现的行为

评价先生成不含等级的共用事实账本，再由管理者报告和七维分析分别解释。账本绑定成果主对象、评价截止日、来源、反证、核验状态和独立的价值／归因判断。产品与研制方法分别记录，另一条评价路径的结论不成为原始证据。

七维必须完成审阅，但不要求七项都有 G。证据不足、不适用、存在冲突均可用明确状态与空档交付，G1 也须引用依据。基本验证不足或关键等级分歧未解决时可以不定 L。两路判断不平均、不取高；等级一致也不代表专家确认。

报告默认依次展示影响力判断、三个关键问题、下一步任务。关键分歧仍在首页提示；七维底稿和完整对照保留。来源弹窗展示已存原文、位置、证明边界、时间与关系信息，并提供有项目权限的原材料下载。未取得的信息不补造，也没有生成替代原文的“证据截图”。

任务草稿可保存、编辑、预览、复制和导出；保存校验版本，解决任务须有本轮证据或专家意见。专家需先被指定，选择、意见、依据与所审版本逐条保存；事实确认与整体确认分开。用户验收、管理员发布和模型完成均不能自动生成专家签认。

重新核验创建待受理工单，保持成果 ID 与主对象，记录变化原因和前一报告。重复请求返回同一工单。新对象从成果提交入口另评；没有可冻结主对象的历史报告不会静默更换对象。旧报告保留，新增报告独立审阅。

## 实时完整流程中的新增修复

拉曼和 NMRexp 各新建一条真实流程，使用原项目截止日 `2026-04-30`，不是原型演示日期。检索变化与固定证据对照分开解释。

1. NMR 原材料同时出现“有效实验记录”和“论文抽取记录”等计量口径。部分可比数据允许保留原值继续建卡，归因明确标为无法比较；不把阈值达成或单位不同的数目算成增长率。
2. 拉曼建卡漏声明一个已引用因素。去掉不合理的因素数量硬上限，增加一次有界的因素引用修复；科学主张、比较数值、成果卡和原文不许更改。
3. 拉曼部分候选引文把相隔段落拼接成了“原文”。增加一次有界的原文修复，读取绑定材料，保持来源 ID 和文档不变，只接受逐字连续片段及真实定位；失败继续阻断，不能删除来源或编造替文。

4. 管理者评价把事实编号当作来源编号时，仅按冻结事实账本展开其原始来源，并保留展开回执；未知编号仍阻断。关联方法事实转存独立底稿，不改写对象 ID，也不作为主产品达级依据。
5. 专家复核使用明确追加序号，避免数据库仅保存到秒时误排整体确认与后续事实意见。

两条完整流程均已完成、通过交付校验并发布本地报告。所有模型日志和私有材料留在本地存储，不写入代码仓库。

## 发布与回退方式

发布脚本 `scripts/package-review-release.py` 将当前 `backend/`、`skills/` 和显式文件名的前端构建打包；输出 `release.json` 与 `compose.release.json`。不打包 `.env`、测试数据、材料、缓存和凭据。使用已有依赖镜像，通过只读挂载固定完整发布包。

`start-docker.ps1` 读取 `.local-runtime/active-release.txt` 中的 Compose 覆盖文件，并使用 `--no-build`。因此以后启动不会静默回到旧容器源码。依赖镜像的准备与本次源代码发布分开。

本次修改前的完整应用、规则、前端与文档位于 `.local-runtime/teacher-v4/baseline/`，数据库备份为同目录的 `database-before.sql`。旧规则执行包存于材料卷的 `evaluation-runtimes/`，已归档 audit-v3 和实际版本号为 `grading-20260925-expert-v2` 的运行代码。

回退时先确认没有运行中的评价任务，选择上一发布包的覆盖配置，再重启 API、worker 和 web。保留数据库新增三表与复核记录，不执行删除式降级。数据库备份用于灾难恢复，不在普通程序回退时覆盖后续合法数据。
