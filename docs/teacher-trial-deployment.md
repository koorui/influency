# 老师试用与服务器部署

当前版本：grading-20260927-coordinated-v5。当前本地发布包为 `.local-runtime/teacher-v4/releases/review-7`，数据库迁移版本为 0015。本地网址仅在运行这套服务的电脑上可用，尚未部署到公网。

## 建议的部署位置

长期试用建议使用一台 Linux 服务器，整体运行 Nginx、FastAPI、MySQL 和评价 worker。阿里云轻量服务器有 [Docker Compose 部署说明](https://help.aliyun.com/zh/simple-application-server/use-cases/manually-deploy-docker)，腾讯云轻量服务器提供 [Docker 环境模板](https://cloud.tencent.com/document/product/1207/60423)。本项目已有 Compose 编排，适合这种部署方式。

小范围老师试用，建议以 4 核 CPU、8 GB 内存、100 GB SSD 作为容量起点。这是按当前单 worker、数据库及材料存储方式作出的工程建议，尚非多人并发压测结论。模型在配置的远端服务执行，应用服务器无需 GPU；模型调用费用另外计算。

服务器地域先综合检查老师访问速度、项目资料可存放的位置，以及当前模型服务的实际连通性。腾讯云官方说明，中国香港及境外轻量服务器无需其 ICP 备案流程，中国内地网站部署须按相关要求办理；详见 [备案资源要求](https://cloud.tencent.com/document/product/243/18908) 与 [阿里云备案场景说明](https://help.aliyun.com/zh/icp-filing/what-scenarios-need-to-be-filed-in-aliyun)。免备案不表示模型服务在该地域一定可用，购买前应核实供应方的服务范围和实际连接。

已有学校或实验室服务器时，可以直接部署到获准使用的 Linux 主机，通过校内网络或已有 VPN 访问，节省另买服务器的成本。

临时演示也可用现有电脑加 Tailscale Serve，把本地服务通过 HTTPS 分享给指定网络成员；电脑和 Docker 必须保持运行，老师需要加入相应网络。它默认只面向网络成员，见 [Tailscale 官方说明](https://tailscale.com/docs/use-cases/application-testing/share-local-dev-server-with-team)。目前没有替用户安装或对外开放此服务。

## 部署时要带走什么

- 新分支源码、当前前端静态产物和服务器可用的依赖运行环境。
- 清理后的数据库及材料卷：保留项目、六份材料、账号和访问授权。仅克隆 Git 仓库不会带走这些数据。
- 私下配置 `.env.docker`、`.deploy-secrets/` 中的模型认证，以及需要时的初始化资料；这些都不进入 Git。
- 在目标 Linux 路径下重新生成发布挂载配置。不要直接使用本机带 `C:/Users/...` 路径的 `compose.release.json`。

当前采用已有依赖镜像加只读源码／静态文件挂载的发布方式，不在本轮重新构建镜像。全新服务器需先准备兼容的运行环境，再应用当前发布包；旧依赖镜像自带代码不能替代 v5 挂载文件。

面向老师的公网入口使用 HTTPS，`.env.docker` 中设置 `DEPLOY_ORIGIN=https://实际域名`、`COOKIE_SECURE=true`。反向代理在同一台服务器时保留应用入口绑定 `127.0.0.1`；数据库保持不映射公网端口。材料与数据库放持久化存储，并设置定期备份。当前 worker 独立执行长任务，不依赖浏览器持续打开。

一次可验收的部署应确认：登录、项目加入、材料上传、提交成果、管理员受理、真实模型调用、完整报告交付和证据下载均可用；最后一步需实际调用模型，不能用健康检查代替。

## 老师怎么使用

1. 给老师访问网址和独立普通账号；也可以让老师在登录页注册。
2. 私下提供该项目安全码，老师输入后加入项目。
3. 老师提交成果名称，你在“工单与工作流”中受理，系统开始评价。
4. 完成后老师在“成果报告”查看主结论、证据及下一步任务。
5. 若要老师提交正式的事实复核意见，再在该报告中指定其账号为审阅人。普通登录不自动获得专家复核权限。

不需要把管理员账号或模型服务密钥发给老师。
