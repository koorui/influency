# V16前端规范

## 信息架构

两栏布局：

- 左：成果列表、送检材料索引
- 右：①影响力等级判断、②关键判断与证据、③下一步任务

## 成果名称快速入口后的轻量提示

若成果由名称自动定位而来，首页不展示检索过程，只在左侧或标题附近保留一个轻量入口：

- 规范成果名；
- 可选：已关联材料数/原始依据数；
- 中低置信时显示“确认成果范围/修改”；
- 高置信时无需打断用户。

不要把别名、候选排序、匹配分数直接铺在首页。

## ① 影响力等级判断

展示顺序：

1. 项目/成果元信息
2. 成果判断（一句话）
3. 当前L级 + 等级名
4. 为什么（2-3条）
5. 提升1级
6. 提升2级

“为什么”中的证据链接显示真实证据标题；内部P/E编号可作为数据主键，但不要成为主要可见文案。

若第三条是“尚不足以进入更高等级”，它是边界判断，不要再次挂前两条正向证据形成重复。

升级卡格式：

**提升1级 → L4｜专业方向显著影响**
- 需要做到：一句话
- 佐证材料：关键词式列出

## ② 关键判断与证据

使用对照表：

| 关键问题 | 项目方材料/主张 | 评价核验 |
|---|---|---|

每格控制为短段落。详细证据通过按钮/链接打开弹窗。

证据弹窗：

- source
- title
- text/quote
- screenshot（内部材料）
- URL（外部来源）
- 必要时写 supports / does_not_prove

## ③ 下一步任务

站在专项办/总师办视角：

- 请项目组补充材料
- 请领域专家确认

首页：任务标题 + 一句话摘要 + `查看任务`。

弹窗：已准备好的可转发文案，可编辑；底部动作分开：

- 编辑/恢复
- 一键复制
- 发送给项目组 / 发送给专家（仅在真实发送能力存在时执行；否则使用“准备发送”或复制）

## 视觉

- 白底、浅灰边框、少量蓝色
- 绿色仅强调当前重要结论
- 橙色仅标关键缺口/尚不能确认
- 不堆叠大段粗体
- 不把解释型副标题做成第二层大标题

## 防溢出

- 所有grid/flex子项 `min-width:0`
- `max-width:100%`
- 长文本 `overflow-wrap:anywhere; word-break:break-word`
- modal `width:min(860px,calc(100vw - 32px)); overflow-x:hidden`
- 按钮/链接可换行，不允许撑破容器
- 移动端两栏改单栏
- 表格在窄屏可横向滚动，正文弹窗不可横向滚动
