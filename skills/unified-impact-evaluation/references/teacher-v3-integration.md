# 2026-09-27 事实驱动评价与审阅协议

本文件是当前运行规则，采用吴老师 v3 Skill 与 0927 前端设计；旧文档中“所有维度强制G”“缺证默认G1”“必须明确L”“固定提升1/2级”的要求由本文件替代。

## 对象、事实与判断

先锁定主评价对象、版本与评价截止日。产品、研制方法、先前基础分别记录，不把方法在研发中的作用记成产品应用。学术真实采用可构成实际作用，不要求销售或商业化。

共用事实账本分别说明 F1形成验证、F2真实任务作用、F3独立外部采用、F4持续多主体影响、F5领域稳定依赖、F6研究或工作方式改变。它们不是必须逐个通过的流程关卡。用原始证据解释状态；系统对证据的理解不是新的原始证据。

事实状态：verified（确切事实有依据）、possibly_happened_but_unverified（有待核线索）、not_found_as_of_cutoff（已检查范围内未找到）、conflict（存在相反依据）。未检查用pending、state=null；不适用用not_applicable、state=null。检索未找到不证明没有发生。核实项目报告写了某指标，不等于核实指标或获得独立认证。

引用冻结原文、位置与来源ID，保留支持／不支持、独立关系、事件与来源时间。不得把日期不明或截止日后的作用认作此前已发生；事后报告须说明时间边界。没有取得原文的来源不支持verified。

## 等级与完成状态

六级名称、七维名称与各档证据条件沿用共同标准。L级由已有实际作用判断，不平均G，不预设逐级或统一人数门槛。下载、镜像、转载、协议、获奖、标准发布本身不能替代实际作用。

每维审阅状态：assessed对应有依据的G1—G5；insufficient_evidence、not_applicable、conflict对应grade=null。G1也须事实支持。not_assessed表示工作未完成，不能导出完成报告。缺证不是低水平。

基本验证不足、对象不清或决定性事实冲突时允许L=null，清楚写出原因与核验任务；不能为了完成任务虚构L1。有级别时引用已核验的达级事实，必要时说明对应真实作用链及独立性依据。关联对象不能代替主对象。

只输出system_preliminary。计算完成、发布、用户验收均不等于专家确认。模型不得生成专家签认或formal认定；旧formal仅按其历史语义读取。

## 独立判断轴

科学／技术价值、项目新增、AI贡献、未来潜力、实际影响和管理建议分别判断。高价值与未来潜力不自动抬高L，参与研发不等于因果净增量。保留阈值／性能／外部基线／因果比较的区别，以及单位、条件与反向证据。

管理者初稿与七维审查使用同一冻结事实包，不把另一份报告结论当来源。统一交付前依 report-quality.md 协调，最终以管理者报告为主；保留未消除的异议及事实冲突，不取高、取低或平均来消除分歧。系统一致也不等于专家已经确认。

## 报告、任务与边界

主报告按“影响力判断→三个关键问题→下一步任务”组织。三个问题是成果价值与先进性、AI与项目贡献、实际影响。项目主张与评价核验分列，AI与项目贡献在底层仍分开。

达级事实按实际数量呈现，不为凑两三条编造。阶段参考是可选的更高事实状态，旧upgrade_plus_1和upgrade_plus_2均为null；L6与未定级不生成升级路径。补交材料可证明已有作用，但材料数量不创造影响。

任务针对真实缺口：补已有材料、专家确认事实边界、观察真实试用、维护证据。专家问题问具体事实、可比性与持续性，不让专家只勾选L4。无缺口可不生成任务，不替项目方安排虚构期限，不自动发送。

任务用 fact_ids 关联本轮明确事实，用 evidence_ids 关联原始来源；没有可绑定记录时留空，不编造编号。任务与已发布报告版本绑定，不因草稿修改而改写科学判断。

拉曼示例：明确评价探针产品还是设计方法，不能按演示L2抄答案。NMR示例：区分独立训练／评测、镜像传播和跨时间持续采用；原型中的外链与等级仍须按本轮截止日核验。
