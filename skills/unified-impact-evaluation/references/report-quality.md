# 管理者主报告：协调与交付检查

管理者报告是唯一面向用户的主结论。七维底稿承担证据审查，不能让读者在两套结论中自行选择。初稿与底稿完成后，统一交付阶段进行一次有记录的协调及表达检查。

## 协调

逐项检查差异涉及的主对象、实际作用、时间、来源独立性和档位条件。仅依据原始材料及本轮有效检索记录修改管理者判断；七维或历史报告的结论不能变成新证据。不强求等级一致，不求平均、不自动取高或取低。

有依据的批评纳入主报告；仍有解释分歧时以管理者报告为主，记录保留意见及理由。决定性事实缺证或冲突时，主报告可以暂不定级。冻结事实或对象有误须重新核验，不能在文字润色中偷换。系统协调不代表专家签认。

特别核对 D2 的本项目新增与既有基础；D6 的研发合作、一次调用和持续集成；D7 的项目自述与有来源的第三方认可。不可仅凭“合作”“论文”“平台”等词定档。

## 最终输出检查

输出前按下面四项检查最终文本，不只检查 JSON 是否合规。发现问题先改文，再提交；协调回执记录实际修改或未改的具体理由，不能只写“全部通过”。

- **流畅度**：按段读一遍，是否能顺着“发生了什么—为何支持判断—还缺什么”读下来？拆开多层转折和长括号；每段只承担一个主要意思。避免在摘要、理由、边界中反复抄同一句话。
- **易懂性**：不看七维底稿，老师能否理解结论？首次出现的必要术语用普通研究语言解释。正文说清谁在什么任务中使用了什么成果、产生什么变化；“事实账本”“证据资格”“影响剖面”等内部术语留在底稿。不能靠删除不确定性来让文字好看。
- **有用性**：说明当前判断对成果凝练和管理意味着什么。每项任务应让读者知道核实什么事实、为何重要、怎样的材料或观察能回答；无需补证就不凑任务。不要只写“加强推广”“完善材料”“进一步提升”。
- **忠实度**：措辞没有扩大对象、时间、独立性或因果范围；数字、引用和不确定边界仍与原始证据一致。润色不能将项目自述改成已获独立验证。

例如，将“主体粒度错配导致F2无法晋阶”改为“现有材料说明设计方法参与了研发，但还不能证明探针产品已在实际任务中使用，因此暂不支持按真实应用提高等级。”下一步写“核对探针用于哪项任务、使用结果和日期，并提供对应使用记录”，而非“补齐F2闭环”。

摘要先交代最重要的作用与判断，详细引用留在对应理由。证据边界必须明确可见；长段说明可以分段或按需展开，但不能用截断后的半句话代替完整结论。
