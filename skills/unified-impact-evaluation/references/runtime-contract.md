# 七维与双层执行契约

引擎来自 v19 交付包，现由统一技能维护。结构版本保留用于读取历史结果，G/L门槛及证据边界读取本技能唯一的当前标准。assets/source-manifest.json 仅记录原始交付来源路径，不表示源码仍与历史交付完全相同。

## 输入和范围

输入为 indicator-workspace.v6，包含项目上下文、冻结成果、证据与显式维度路由。先使用 scripts/v19.py inspect 检查。原始材料或裸成果名需先定位建卡，不能用标题相似强绑历史成果。平台新工单可根据已冻结建卡证据生成工作区；外部工作区必须提供审查过的 ID 映射。

本轮仅评价指定成果或明确的成果集合，保留特定层、全局层和协同分析，不把单成果扩大成整个项目。共用标准不意味着把管理者报告结论当作七维原始证据。

## 执行

scripts/requirements.txt 覆盖管理者报告校验和模型执行依赖。inspect 不需要模型服务；run 需要显式配置 V19_API_KEY、V19_BASE_URL、V19_MODEL，或由平台使用现有 codex 传输。不得从材料或其他项目读取凭据。

run 在独立子进程执行，输出目录必须是新的目录，保留原始输入、响应、失败及运行记录。运行清单记录模型、服务地址和版本，不包含密钥或文件摘要。当前不复用历史模型调用以代替新调用。

每个成果执行七次维度判断和一次成果综合，最终执行一次范围综合，共 8N+1 次逻辑调用；重试会增加实际调用。平台阶段任务只执行请求的阶段，不在模型调用内再次启动引擎。

## 输出和校验

管理者结果与七维结果都记录 unified-double-layer-impact.v1 和 grading-20260925-1930。结构标识 wu-outcome-v2.1、indicator-evaluation.run.v5 及引擎版本保留兼容含义，不另行定义等级标准。

输出包括 evaluation-run.json、product.json、preflight.json、validation.json 与运行日志。完成结果必须有七个G级、成果L级及范围L级。引用必须来自实际输入，G2及以上和L级需要相应事实支持。校验失败保留底稿，不生成假模型结果。

统一导出保留 wu-evaluation.json、v19-evaluation.json，并新增 unified-evaluation.json 和规则版本。相同对象的L级与各G级逐项对照；缺失、版本不明或混合历史结果明确标记，不自动盖上新标准标识。结构校验不替代事实核验或用户验收。
