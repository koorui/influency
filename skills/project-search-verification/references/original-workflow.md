你需要一次性完成一个“影响力评估项目 Search 验证”任务。

本任务包含三个相互关联的模块：

1. 核验项目报告中所宣称的对比方法、原始指标及评审时点的真实 SOTA；
2. 追溯项目承担团队及相关学校、学院、研究所在项目启动前已有的论文、专利和研究成果；
3. 核验截至对应阶段评审时间，项目成果是否被使用、部署、评价，是否存在新闻、微信公众号、媒体或自媒体报道。
4.对项目所宣称的相关成果github仓库进行整理，判断仓库价值与可复现性。
5. 待填写的search输入，内有多条已经整理好的指标，你需要判断这些项目声明的指标是否达到，并给出判断执行度。

五个模块必须在一次任务中完成，不要拆成三次执行。

# 一、核心时间限制

本任务采用“阶段评审时点审计”原则。

虽然网络检索发生在当前日期，但所有用于评价项目成果、SOTA、既有成果、外部使用、部署、引用和媒体影响的正式证据，必须控制在项目所提供报告对应的时间范围内。

例如：

- 如果项目材料是阶段性评审报告，则以该阶段评审日期或数据统计截止日期为证据截止日；
- 如果不同成果属于不同评审阶段，应分别设置对应的评审基准日；
- 不得使用评审日之后发表的论文、产生的引用、代码更新、第三方复现、部署案例或媒体报道，反向证明项目在评审时已经达到相应水平或产生相应影响。

检索可以在当前执行，但必须分别记录：

- 当前检索日期；
- 来源首次公开日期；
- 事件实际发生日期；
- 对应阶段评审基准日；
- 是否处于有效时间窗口。

评审基准日之后出现的结果不得纳入正式结论，只能记录在“超出评审时间窗口排除清单.csv”中，以防止误用。

不得出现没有时间限定的“当前SOTA”“当前引用量”“截至检索日影响力”等结论。所有相关表述应统一写成：

“截至对应阶段评审基准日”。

# 五、团队和机构范围

团队成员与学校、学院、研究所的一般同领域人员必须分开。

统一采用以下身份层级：

- A级：任务书、项目名单、正式项目材料或个人官方主页明确列为项目成员；
- B级：论文明确致谢项目编号，但没有正式成员表；
- C级：承担单位同领域研究人员，与项目技术路线相关；
- D级：外部相关研究人员，仅存在技术关联。

不得把承担单位、学校或学院所有同领域人员自动认定为项目成员。

团队成果和学校学院成果必须分别整理：

1. 团队成员既有论文；
2. 团队成员既有专利；
3. 团队成员其他研究成果；
4. 学校、学院、研究所或实验室既有研究成果。

“项目内部或关联方”应包括：

- 项目负责人；

# 六、模块一：SOTA与对比指标验证

## 6.1 目标

通过网络检索，核验项目材料中所宣称的：

- 对比方法；
- 对比方法原始水平；
- 对比方法原始指标；
- 项目方法指标；
- SOTA声明；
- 性能提升比例；
- 其他方法可能的实际表现。

SOTA必须定义为：

“截至对应阶段评审基准日，在相同或可比测评协议下公开可获得的最佳结果。”

不得使用评审基准日之后发表的新方法或新结果评价项目在该阶段是否达到SOTA。

如果没有公认的单一SOTA，应列出多个合理候选，并说明数据集、版本、参数和测评条件差异。

## 6.2 原始方法和指标检索

对项目材料中出现的每个对比方法，优先查找：

1. 原始论文；
2. 期刊或会议官方页面；
3. 论文PDF；
4. 官方代码仓库；
5. 官方数据集或排行榜；
6. 作者公开结果；
7. 评审基准日前的第三方复现或基准测试。

必须忠实记录：

- 数据集名称和版本；
- 训练集、验证集和测试集划分；
- ID/OOD或插值/外推条件；
- 样本数量；
- 模型参数量；
- 模型骨干；
- 训练数据规模；
- 预训练或额外数据；
- 训练超参数；
- 推理预算；
- 迭代次数；
- 指标名称；
- 指标定义；
- 指标方向；
- 原始数值；
- 均值和标准差；
- 原论文表格和页码；
- 作者自测或第三方测评。

只要以下内容不同，就必须明确记录：

- 数据集；
- 数据集版本；
- 数据划分；
- 参数量；
- 骨干网络；
- 输入输出；
- 训练数据；
- 预训练方式；
- 推理预算；
- 指标定义；
- 是否使用额外先验。

不得把不同协议的数字直接并列后宣称优劣。

## 6.3 论文声明与评审时点SOTA核验

分别判断：

- 项目引用的对比方法指标是否与原论文一致；
- 项目是否遗漏了评审基准日前已存在的更强方法；
- 项目所称的SOTA是作者自称还是公开排行榜结果；
- 项目方法与真实SOTA是否使用相同协议；
- 项目所声明的提升比例是否计算正确；
- 在忠实考虑参数和数据差异后，项目声明是否成立。

## 6.4 其他方法实际指标估计

如果无法找到完全相同协议下的其他方法结果，可以进行谨慎估计，但必须遵守：

1. 实测值与估计值分开；
2. 给出估计区间；
3. 不得虚构精确小数；
4. 写明推算依据；
5. 写明关键假设；
6. 给出估计置信度；
7. 判断估计结果是否可能支持项目论文声明。

可使用的估计依据包括：

- 原始论文相近实验；
- 官方代码结果；
- 评审基准日前的第三方复现；
- 相邻参数规模；
- 相似数据集；
- 消融实验；
- 公开排行榜。

评审基准日之后的第三方实验不得用于正式估计，只能列入时间窗口排除表。

- 数据集；

- 代码版本；
- 项目启动前后的新增内容。

科研项目允许在已有基础上继续研发。发现复用不等于认定违规，不得直接作不当申报结论。

应客观说明：

- 项目前基础；
- 项目期新增量；
- 复用程度；
- 证据缺口；
- 判断置信度。

# 八、模块三：成果使用、评价和媒体报道

## 8.1 目标

检索截至对应阶段评审基准日，项目相关成果是否：

- 被外部单位实际使用；
- 被采购；
- 被部署；
- 被第三方复现；
- 被后续论文作为基线运行；
- 被引用；
- 被综述评价；
- 被代码仓库关注；
- 被新闻报道；
- 被微信公众号、自媒体或社交媒体介绍；
- 被项目内部平台或合作单位使用。

## 8.2 使用证据分级

统一分为：

- A级：外部实际运行、采购、部署、现场应用或验收；
- B级：明确复用代码、模型、软件、数据库或数据；
- C级：普通论文引用、综述、书目收录、Star、Fork、Issue；
- D级：项目组、承担单位、合作单位或合作企业内部使用或自述；
- E级：公开检索未发现有效结果。

以下情况不得自动算作实际使用：

- 普通引用；
- 浏览量；
- 下载量；
- Star；
- Fork；
- 媒体转述；
- AI自动论文摘要；
- 项目采购；
- 作者自测。

## 8.3 外部性和内部性

对每项使用、评价或报道分别判断：

- 是否确实对应本项目成果；
- 是否为同名误命中；
- 是否属于项目启动前成果；
- 使用者是否为项目成员；
- 使用者是否为同一实验室；
- 使用者是否为项目承担单位；
- 是否为合作单位或合作企业；
- 是否为独立第三方；
- 是否真的运行或部署；
- 是否只是引用或转述；
- 是否在评审基准日前发生并公开。

每项判断均需单独给出置信度。

## 8.4 媒体与自媒体

对新闻、微信公众号、自媒体和社交媒体文章追溯来源链：

- 原始机构稿；
- 企业供稿；
- 政府网站转载；
- 行业网站转载；
- 同文转载；
- 作者本人发布；
- AI自动摘要；
- 独立记者或第三方评价。

同一文章被多个网站转载时，只能算一个来源链，不得算作多个独立报道。

必须区分：

- 项目目标；
- 预期指标；
- 作者自报结果；
- 已完成结果；
- 已验收结果；
- 第三方复测结果；
- 用户实际评价。

不得把目标、预算、招标或采购写成已经形成的技术成效。

# 十、证据保存

优先保存：

1. 项目原始材料；
2. 原始论文PDF；
3. 期刊或会议官方页面；
4. 官方代码仓库；
5. 官方数据集或排行榜；
6. 正式专利页面；
7. 政府、学校、学院、研究所官方网站；
8. 正式采购或验收页面；
9. 新闻、微信公众号或自媒体页面。

保存格式：

- 网页保存为 `.html`；
- 论文、专利和报告保存为 `.pdf`；
- API或元数据可保存为 `.json`；
- 关键页面和关键指标保存为 `.png`截图；
- 报告保存为 UTF-8 `.md`；
- 表格保存为 UTF-8 `.csv`，建议带BOM以便Excel直接打开。

不要求保存每一个普通搜索结果页。应重点保存直接支持结论的原始证据和关键反证。

证据文件建议采用以下命名：

模块一：

- SOTA-E001_来源_内容说明.html
- SOTA-E002_论文简称.pdf
- SOTA-SS001_指标表第X页.png

模块二：

- PRE-E001_人员或机构_成果说明.html
- PRE-E002_论文或专利.pdf
- PRE-SS001_关键页面.png

模块三：

- IMP-E001_媒体或使用单位_内容说明.html
- IMP-E002_第三方测评论文.pdf
- IMP-SS001_报道或指标页.png

如果网页存在验证码、403、登录限制或付费墙：

1. 保存能够访问的页面或元数据；
2. 保存URL；
3. 记录访问受限；
4. 不得假装已经读取无法访问的正文；
5. 不得仅凭搜索摘要作高置信度结论。

# 十一、负检索和误命中

必须主动排除：

- 同名论文；
- 同名模型；
- 同名软件；
- 同名数据库；

- 前序版本与项目期版本混淆；
- 项目采购与成果部署混淆；
- 普通引用与实际使用混淆；
- 内部稿与独立报道混淆；

不得写：

- “绝对无人使用”；
- “该成果不存在”；
- “没有任何报道”。

# 十二、置信度

置信度表示当前证据支持该判断的把握，不是统计概率，也不是违规概率。

参考口径：

- 90%—100%：原始论文、正式项目材料、官方代码、专利或用户原始材料直接支持；
- 70%—89%：证据链较完整，但项目归属、人员身份或部署细节仍有缺口；
- 50%—69%：存在合理关联，但缺少任务书、项目号、版本或验收材料；
- 低于50%：公开证据不足，只能作为待核线索。

以下置信度必须分别判断：

- 对象对应置信度；
- 团队成员身份置信度；
- 项目内部性置信度；
- 真实使用或部署置信度；
- 指标可比性置信度；
- 项目期归属置信度；
- 前序成果复用判断置信度；
- 项目声明成立置信度；
- 时间窗口判断置信度。

不得用一个综合置信度替代所有判断。
